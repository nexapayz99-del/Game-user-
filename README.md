# Game User — single-owner Pyrogram game assistant

                         AAKASH👑

This is a hardened replacement architecture for the uploaded prototype. It uses:
- One owner-authorized Pyrogram user session, supplied locally as `USER_SESSION`
- A separate Telegram bot token for `/status`, `/pause`, `/resume`, `/session`, `/join`, and `/leave`
- MongoDB via Motor for persistent run state and event/error metadata
- A configurable target group and optional game-bot username filter
- Word-length parsing for common prompt formats
- A serialized sender with a minimum 5-second gap between replies
- Safe startup/shutdown, structured logging, environment validation, and systemd deployment

## Important design choice
This project intentionally does **not** collect other people's OTPs, 2FA passwords, or string sessions. Do not send your `USER_SESSION`, bot token, API hash, or MongoDB URI to anyone. The user session must belong to an account you own or are explicitly authorized to operate.

## Requirements
- Ubuntu VPS
- Python 3.10+
- MongoDB Atlas or a reachable MongoDB instance
- Telegram API credentials from `my.telegram.org`
- A bot token from BotFather
- A Pyrogram string session generated for your own account using a trusted local workflow

## Setup
```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip
sudo mkdir -p /opt/game-user
sudo chown "$USER":"$USER" /opt/game-user
# Upload and extract this ZIP into /opt/game-user, then:
cd /opt/game-user
python3 -m venv .venv
. .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
nano .env
```

Fill every required value in `.env`. Use a numeric Telegram group ID, usually a negative number such as `-1001234567890`. `ADMIN_IDS` is a comma-separated list of Telegram numeric user IDs.

Run a configuration check:
```bash
. .venv/bin/activate
python app.py --check-config
```

Run interactively:
```bash
python app.py
```

## systemd
Edit `game-user.service` and replace `/opt/game-user` and `YOUR_LINUX_USER` if needed. Then:
```bash
sudo cp game-user.service /etc/systemd/system/game-user.service
sudo systemctl daemon-reload
sudo systemctl enable --now game-user
sudo systemctl status game-user
journalctl -u game-user -f
```

Restart after changing `.env`:
```bash
sudo systemctl restart game-user
```

## Private control-panel commands
- `/start` or `/help` — open the control panel
- `/status` — runner state, target group, membership/access status, account ID
- `/session` — show the connected account's Telegram ID and username (never reveals the secret string session)
- `/join @publicgroup` — join a public group/channel by username
- `/join https://t.me/+invitecode` — join using an invite link the account is permitted to use
- `/leave @groupusername` — leave a group
- `/leave -1001234567890` — leave a group by chat ID
- `/leave target` — leave the configured target group
- `/pause` and `/resume` — pause/resume automatic replies

Commands and inline buttons are restricted to IDs in `ADMIN_IDS`. Join/leave changes membership only; the game runner still listens only to `TARGET_GROUP_ID`. If you leave that target, it cannot read or reply there until the account rejoins.

## Group configuration
1. Add the user account (the account represented by `USER_SESSION`) to the target group.
2. Add the control bot to the group only if you want its commands visible there; it can also be used in a private chat.
3. Set `TARGET_GROUP_ID` to the numeric group ID.
4. Optionally set `GAME_BOT_USERNAME` without `@` to only accept prompts from that sender. Leave empty to accept matching prompts from any sender in the configured group.
5. Confirm the account is allowed to send messages in that group.

## Safety and operations
- A 5-second gap is enforced between replies generated by this process. Telegram can still impose FloodWaits; the delay is not a guarantee against rate limits.
- The app backs off when a FloodWait is raised and logs recoverable errors.
- Only one process should run for a given session. Do not start a second copy using the same session.
- Keep `.env` out of version control. The service file runs as a non-root Linux user.
